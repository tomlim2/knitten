# shotloom — 2026-04-23

## ADR-0029 정규화 레이어 설계 — 초안에서 최종안까지

### 배경

- `shotloom-retarget` 가 정규화 로직까지 떠안고 있었음 (`adapters::arp_vrm::align_full_body_rest`, `vrm_rest`, foot contact 등이 retarget math 와 같은 크레이트에 섞임)
- Multi-source 로드맵 (VRM 오늘 / FBX / PMX) — post-import 은 source-agnostic 해야 함
- A-pose 전환이 미래 예정. 전환을 어떻게 구조로 대비할지가 관건
- shotloom 은 편집툴. face / body 양쪽 채널 편집, TTS 향후 합류 고려 필요

### 이력 (방향 전환 3회)

**1. 초기 안**: canonical rest pose enum (`CinevArpV1`, `APoseV1`) + `ACTIVE_CANONICAL_POSE` const + 캐시 키 태그

→ 리뷰 결과 **거절**. A-pose 수학 명세가 없는 상태에서 enum 두 번째 variant 는 dead code. 광고하는 미래 shape 은 premature abstraction.

**2. 방향 전환**: enum/태그 전부 드롭. `normalizer crate 분리만` 을 핵심으로 축소

**3. 진입점 재설계**: `CharacterModel` 안에 `rest_pose: Option<RestPose>` 필드 내장. source 포맷 지식 소거. `#[serde(skip)]` 로 디스크 스키마 호환

**4. Character-neutral contract 명시**: NormalizedAnimation 이 character-agnostic. 한 번 정규화, 여러 캐릭터 재사용

**5. Type ownership open question**: `NormalizedAnimation` 이 core / per-normalizer / 별도 types crate 중 어디에 사는지는 결정 보류. Leading: `shotloom-core`

**6. Scope creep 한 번**: Track/Clip cross-link 추가했다가 제목 밖이라 revert

### 핵심 결정 (최종안)

| | 결정 |
|---|---|
| 새 crate 2개 | `shotloom-character-normalizer`, `shotloom-animation-normalizer` |
| CharacterModel 확장 | `rest_pose: Option<RestPose>` (serde-skip) |
| 타입 위치 | `RestPose` 는 `shotloom-core`. `NormalizedAnimation` 은 open question (leading: core) |
| Retarget 시그니처 | `retarget(&CharacterModel, &NormalizedAnimation) → TargetAnimation` |
| Animation contract | character-neutral. normalize 1회 / retarget N회 |
| 안 만드는 것 | `CanonicalPoseId` enum, `ACTIVE_CANONICAL_POSE` const, per-asset pose 태그 — A-pose 올 때 결정 |

### Rejected alternatives (5)

- **A** retarget crate 에 정규화 유지 → 덤프 그라운드화
- **B** CanonicalPoseId enum 지금 도입 → premature, dead variant
- **C** 단일 shotloom-normalize crate → character/animation 변경주기 disjoint, 격리 가치
- **D** rest_pose 를 serde persist → outliner/inspector 가 shape 변화에 커플
- **E** RestPose 를 CharacterModel 옆에 별도 pass → caller 마다 pair 수동 운반 부담

### 러닝

- **ADR 수정 자유도는 status 에 달림** — Proposed 단계라 마지막까지 편하게 다듬었음. Accepted 뒤였으면 supersede ADR 필요
- **"Earn the abstraction now, 근데 데이터 모델 부분만큼은 아님"** — 구조(crate 분리, 타입 계약) 는 미래 대비해서 미리 잡되, 런타임 태그 / 버전 enum 같은 데이터 모델은 실제 필요할 때까지 미룸. ADR-0029 가 이 균형 찾는 데 시간 씀
- **타이틀이 scope 의 gate** — Track/Clip cross-link 가 의미적으로 자연스러워도 제목이 "Normalizer Crate Layer for Import" 면 downstream 편집 얘기는 빠지는 게 맞음. ADR 이 scope 커지면 리뷰어가 못 읽음
- **Character-neutral contract 은 편집기 관점에서 배당 받음** — 편집 UI 설계(트랙, 오버라이드) 얘기 나오면서 "한 anim 을 여러 캐릭터에 재사용" 이 실전 가치로 drop. 그래서 ADR 본문에 1급으로 박힘
- **TTS 아직 stub** — stub 을 현재 동작 consumer 인 것처럼 가정하고 ADR 초안 작성했다가 정정. 향후 실제 있는 것 vs 계획만 있는 것 분별 필요
- **"Character-neutral" 원칙이 편집툴 아키텍처 전체를 리드** — NormalizedAnimation 이 신뢰할 만한 canonical 이면 그 위에 레이어링 / 오버라이드 / TTS 합류 / AI 생성 합류 전부 자연스럽게 정리됨
