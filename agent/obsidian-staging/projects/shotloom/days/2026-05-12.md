# Editor debug surface and overlay layering groundwork

## Big picture

라우터 셸 위에 디버그 도구(리타게터, env 등)를 붙이기 전, editor shell의 **레이아웃 어휘**와 **오버레이 계층 규칙**을 먼저 못박는 groundwork. UI 표면이 자라기 전에 vocabulary가 자라야 follow-up panel PR마다 같은 논의를 다시 안 함.

## Why

라우터 셸은 `/`만 다루고 있었음. `/debug/*` 하위에 panel을 붙이려는데 세 가지가 동시에 흐트러질 위험:

- **layout 어휘** — preset / panel / panel-collection 중 무엇으로 부를지 정하지 않으면 첫 panel이 vocabulary를 결정하고 나머지가 끌려옴.
- **overlay z-stack** — toast viewport는 `INT32_MAX` 리터럴로 떠 있는데, modal이 들어오는 순간 그 위 어떻게 쌓을지 정해진 게 없음. 컴포넌트마다 ad-hoc z-index가 정착하면 천장까지 ratchet up 됨.
- **route subtree 종속성** — toast가 `<ToastProvider>` 자식으로만 떠 있으면, route가 큰 화면을 잡는 순간 overlay 수명이 route에 묶여서 navigation 직전 발사된 toast가 같이 사라짐.

이 PR은 그 세 가지에 답을 박아두고, 실제 디버그 content는 후속 PR로 미룸.

## How

- 라우트 컨테이너 `DebugSurface`를 `<Route path="/debug/*" element={…}>`로 등록. trailing path는 `useParams("*")`로 읽어서 registry lookup. nested routes 안 씀 — 패널 하나가 nested data loader 필요해질 때까지는 flat registry가 boilerplate 더 작음.
- vocabulary는 `DebugSurface`(route 컨테이너) + `DebugPanel`(leaf). `preset`은 카메라 프리셋과 충돌해서 reject, `panel-collection`은 grouping이 아직 필요 없어서 reject. 이 rationale은 module README에 남김 (ADR 본문에는 컴포넌트 이름 안 적음 — rename 따라 무너짐).
- overlay z-stack 토큰은 `components/overlay/overlayLayers.ts` 한 파일로 통합. `OVERLAY_Z_TOAST` / `OVERLAY_Z_MODAL` 두 개 토큰을 큰 간격(1e8)으로 띄워서 사이에 layer 끼울 여지를 둠. `ToastViewport`는 INT32_MAX 리터럴 대신 `OVERLAY_Z_TOAST`를 읽음. modal은 아직 consumer 없지만 invariant test (`MODAL > TOAST` + 간격 ≥ 1e6) 한 줄로 순서를 컴파일/CI 레벨로 잠금.
- durable claim — **overlay는 route React subtree에 종속되지 않고, stacking order는 단일 token 파일에서 잠긴다** — 만 ADR로 분리. 라우터 결정은 기존 ADR이 이미 owner라 거기 손 안 댐.
- viewport invariant는 그대로 — `<ViewportArea />`가 `RoutePreset` 바깥에 있어서 navigation으로 remount 안 됨. router test가 mount count == 1을 navigation 왕복 이후에도 검증.

## What

- 새 모듈: `components/debug/` (DebugSurface, DebugPanel.types, debugPanels, PlaceholderDebugPanel, CSS module, breadcrumb README, unit tests)
- 새 모듈: `components/overlay/overlayLayers.ts` + invariant test
- `App.tsx` `RoutePreset`에 `/debug/*` 등록 + 그리드 placement용 `DebugRoutePreset` 래퍼
- `ToastViewport`는 토큰 import로 전환
- ADR 1장 추가 (Proposed) — overlay 계층 규칙만, 좁게
- MAP.md에 debug 모듈 + overlay 토큰 라인 추가, ADR 인덱스 Proposed 섹션 추가

테스트는 14개 통과 — DebugSurface 단위 4개, 토큰 invariant 2개, App router 6개(기존 3 + 신규 3: /debug mount, navigation no-remount, unknown slug fallback), toast smoke 2개.

## 사이드 노트

- ADR 가이드라인 리트머스 — "크레이트/타입/파일 이름이 바뀌어도 문단이 유효한가?" 적용했더니 세 결정 중 하나(overlay 규칙)만 ADR 자격이 있었음. 컴포넌트 네이밍은 README, nested route 패턴은 기존 라우터 ADR이 이미 커버. ADR을 자동으로 세 개 안 쓰게 된 게 self-review의 실효였음.
- 자기 리뷰에서 P3 두 개 잡힘: ADR Context의 "in the near future" 시간 표현, 그리고 `OVERLAY_Z_MODAL` 토큰이 consumer 없고 invariant test도 없어서 잠금이 doc-only였던 점. 둘 다 코멘트로만 보장하면 review round-1에서 다시 지적 받았을 패턴.
- `gridColumn: 1; gridRow: 1 / -1` 트릭으로 기존 AppShell 그리드를 안 건드리고 `/debug/*`에서 좌측 컬럼 풀 높이를 잡음. timeline row가 `auto`라 콘텐츠 없으면 0으로 collapse — viewport는 우측 컬럼에서 풀 높이 유지. 그리드 템플릿 분기 안 해도 됨.
