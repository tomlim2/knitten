# Shotloom devlog 2026-05-20

## PR 368

1. 지적 — Rust 2021 sibling module re-export는 `self::`로 qualify한다.
   Review는 `crates/shotloom-engine/src/bridge/handlers/stage/mod.rs`의
   `use boundary::...`, `use edit::...`, `use lifecycle::...`가 current
   `stage` module 기준 relative path로 resolve되지 않고 crate/external path를
   찾는다고 지적했다. Facade split은 dispatcher surface를 보존해야 하므로,
   compile failure가 나면 handler body equivalence 이전에 routing contract가
   깨진다. -> `0e9e4318`에서 sibling re-export가 `self::boundary`,
   `self::edit`, `self::lifecycle`로 qualify됐다.

2. 지적 — 같은 visibility scope는 같은 spelling으로 유지한다. Review는
   `crates/shotloom-engine/src/bridge/handlers/stage/mod.rs`의 legacy wrapper
   handlers가 `pub(in super::super)`를 쓰고, 새 dispatcher-visible re-export block은
   `pub(in crate::bridge)`를 써서 semantically same scope를 두 spellings로
   표현한다고 봤다. Visibility spelling은 grep 가능한 dispatcher surface의 일부라,
   같은 boundary를 다르게 쓰면 다음 refactor에서 drift가 재도입된다. ->
   `2c08c847`에서 `handle_set_clear_color`, `handle_set_stage_mood`,
   `handle_new_bundle_command`가 `pub(in crate::bridge)`로 정렬됐다.

> [!abstract] Rule
> Rust facade modules should make sibling imports explicit and keep dispatcher
> visibility spelling uniform. Compile-time path resolution and grep-friendly
> ownership boundaries are part of the refactor contract. #rule

## PR 371

1. 지적 — bridge diagnostic payload는 runtime skew를 전제로 guard한다.
   Review는 `apps/editor/src/components/debug/StageImportDebugPanel.tsx`의
   `validation_diagnostics` subscriber가 `payload.diagnostics`를 array 검증 없이
   state에 저장하면, 다음 render의 `.slice()` / `.map()`에서 crash할 수 있다고
   지적했다. Bridge event는 JSON parse 뒤 TS type assertion만 거치므로, UI boundary는
   malformed payload를 invalid input으로 다뤄야 한다. -> `328aa032`에서
   `Array.isArray` guard가 들어가고 malformed payload는 저장하지 않도록 바뀌었다.

2. 지적 — command terminal precedence는 multi-event regression으로 pin한다.
   Review는 `commandStatus`가 rejection/runtime error를 completion보다 우선하는
   refactor를 했지만, tests가 terminal event를 하나씩만 넣어 pre-PR `.find()` 방식으로
   되돌려도 통과한다고 지적했다. Ordering bug는 `bundle_changed`와
   `command_rejected`가 같은 command id에 함께 있을 때만 드러난다. -> `6c1fbfd8`에서
   same-command `bundle_changed` 이후 `command_rejected`가 와도 failed status가 이기는
   regression이 추가됐다.

3. 지적 — intermediate clear command id도 failure surface에 포함한다. Review는
   map load 전 `clear_background_props` command id를 버리면, 그 clear가
   `command_rejected`나 `runtime_error`를 내도 active load command와 correlate되지 않아
   panel에도 toast에도 드러나지 않을 수 있다고 봤다. Pre-load clear가 stale props를
   남길 수 있으면 load completion만 보는 status는 거짓 성공이 된다. -> `6c1fbfd8`에서
   clear command id를 auxiliary id로 추적하고, completion은 load command에 묶되
   rejection/runtime error는 auxiliary events까지 반영하게 됐다.

4. 지적 — bounded diagnostic UI는 overflow, pluralization, duplicate keys를 test한다.
   Review는 `hiddenDiagnosticCount > 0` branch가 test되지 않았고, identical
   severity/code/message diagnostics가 React key collision을 만들 수 있으며,
   "1 more diagnostics" copy도 어색하다고 지적했다. Debug UI의 diagnostic list는
   rare branch일수록 regress하기 쉬운 operator surface다. -> `328aa032`와 `6c1fbfd8`
   에서 overflow rendering, duplicate-safe occurrence suffix, no duplicate-key warning
   regression, singular/plural overflow label이 추가됐다.

5. 지적 — memoization dependency는 stable source에 걸어야 한다. Review는
   `visibleDiagnostics = latestCommandDiagnostics.slice(0, 3)`가 render마다 새 array를
   만들기 때문에 `useMemo([visibleDiagnostics])`가 매번 invalidate되어 memoization이
   실제로 작동하지 않는다고 봤다. 작은 list라도 code intent와 runtime behavior가
   어긋나면 다음 edit에서 잘못된 최적화로 읽힌다. -> `6c1fbfd8`에서 diagnostics slice가
   stable state dependency 기준으로 memoized됐다.

6. 지적 — fixture provenance lookup은 launch cwd가 아니라 test file location에
   anchor한다. Review는 S2M manifest lookup이 `process.cwd()`에서 위로 걷는 방식이면
   IDE, repo-root, sandboxed cwd마다 실패 지점이 달라진다고 지적했다. Fixture-quality
   test는 launch directory가 아니라 fixture/test file 위치에 묶여야 한다. -> `6c1fbfd8`
   에서 `fileURLToPath(import.meta.url)` 기반으로 test file location에서 upward search를
   시작하게 바뀌었다.

> [!abstract] Rule
> Event-driven debug panels need tests with competing terminal events, malformed
> payloads, auxiliary command failures, overflow diagnostics, and duplicate rows.
> Single-event happy paths do not prove status precedence. #rule

> [!abstract] Rule
> Fixture provenance tests should resolve from the test file or fixture root, not
> from process launch cwd. Cwd-dependent tests are environment probes, not stable
> contract tests. #rule
