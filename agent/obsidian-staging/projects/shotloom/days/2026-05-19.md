# Shotloom devlog 2026-05-19

## PR 358

1. 지적 — validation-rule renumber는 모든 cross-reference를 같이 갱신한다.
   리뷰는 bundle format validation rule에 Stage reference rule이 추가되면서
   뒤쪽 규칙 번호가 밀렸는데, `bundle-format.md`와
   `autosave-and-persistence.md`의 old references가 남았다고 지적했다. 문서
   번호는 implementation보다 조용히 stale해지기 쉽고, validation/error policy
   문서에서는 잘못된 rule number가 reviewer와 implementer를 다른 contract로
   이끈다. → `2de25e14`에서 관련 cross-reference가 `§17 rules 1-17`과
   `§17 rule 18`로 맞춰졌다.

2. 지적 — validation spec은 id scope를 정확히 분리해야 한다. 리뷰는 Stage
   validation rule이 `stage/element/renderable ids are unique within their
   Stage scope`라고 쓰여 있어 stage id까지 per-Stage scope처럼 읽힌다고 봤다.
   실제 Rust source of truth는 `ShotModel::validate_stage_refs`이고, stage id는
   shot scope, element/renderable id는 containing Stage scope다. → `2de25e14`
   에서 rule wording이 scope를 분리하고 Rust source of truth를 명시했다.

3. 지적 — serde bool default helper는 한 곳에서 재사용한다. 리뷰는
   `stage.rs`가 `serde_helpers.rs`의 `default_true`, `is_true`, `is_false`와
   같은 helper를 다시 정의한다고 봤다. default/skip predicate는 작아 보여도
   serialization contract라 중복되면 drift point가 된다. → `2de25e14`에서
   Stage model은 shared serde helpers를 import하고 local duplicates를 제거했다.

4. 지적 — populated valid graph도 validation happy path로 pin한다. 리뷰는
   Stage serde round-trip fixture가 `validate_stage_refs()`를 호출하지 않아,
   non-trivial valid Stage graph가 거짓 reject되는 regression을 잡지 못한다고
   했다. Error-path tests만 있으면 validator가 너무 엄격해지는 쪽의 실패가
   숨는다. → `2de25e14`에서 populated Stage round-trip test가 validation
   success를 확인하고, 별도 test가 per-Stage element/renderable id scoping을
   고정했다.

## PR 356

1. 지적 — documented no-op command는 UI에서 terminal state가 있어야 한다.
   리뷰는 `clear_background_props` no-op이 bridge contract상 correlated event를
   내지 않는데, panel status가 correlated event만 기다리면 "command accepted"에
   영원히 머문다고 지적했다. Debug surface의 역할은 command outcome을 보여주는
   것이므로, eventless accepted no-op도 사용자-visible completion으로 변환해야
   한다. → `667ec9a7`에서 clear no-op path가 local timer를 통해 "no background
   props to clear" completion message로 전환됐다.

2. 지적 — no-op timer는 event buffer 전체가 아니라 active command identity에
   묶는다. 두 번째 review는 unrelated bridge event가 올 때마다 `recentEvents`
   effect가 timer를 취소/재시작해서 no-op success가 무기한 지연되거나 success
   message가 accepted state로 되돌아갈 수 있다고 봤다. No-op command는
   correlated event가 없으므로 unrelated event stream과 독립적으로 완료되어야
   한다. → `85db0513`에서 no-op timer/reset이 active command id/type과
   correlated event 여부에만 묶였고, unrelated events before/after timeout
   regression이 추가됐다.

3. 지적 — batch command completion은 terminal sentinel만 사용한다. 리뷰는
   `prop_added`/`prop_removed`가 batch 중간 event인데 panel이 이를 completion
   event로 취급하면 72개 placement 중 첫 prop event에서 "completed"가 되어
   아직 남은 spawn을 숨긴다고 지적했다. Engine contract의 terminal sentinel은
   trailing `bundle_changed`다. → `667ec9a7`에서 status completion은
   `bundle_changed`만 terminal로 보고, prop events는 accepted/in-progress 상태에
   남게 됐다.

4. 지적 — fixture grid test는 trivial first placement만 보면 안 된다. 리뷰는
   `placements[0]`이 항상 row/column/rotation/translation의 trivial corner라,
   column wrap, row stride, rotation cycle, ordinal padding을 검증하지 못한다고
   했다. Large fixture behavior는 large-index spot check가 있어야 한다. →
   `667ec9a7`에서 72-placement case가 wrap point와 final placement의 object id,
   translation, rotation을 검증하게 됐다.

5. 지적 — capped event buffer와 consecutive dispatch는 status model의 별도
   contracts다. 리뷰는 50-slot `recentEvents` buffer에서 72 prop events와
   trailing `bundle_changed`가 살아남는지, 그리고 이전 command failure가 다음
   command의 accepted state를 오염하지 않는지 테스트가 없다고 봤다. →
   `667ec9a7`에서 capped-buffer success regression과 consecutive dispatch
   replacement regression이 추가됐다.

> [!abstract] Rule
> Event-driven debug UI는 command acceptance와 terminal completion을 같은 것으로
> 취급하지 않는다. No-op, intermediate events, capped buffers, unrelated events는
> 각각 별도 contract로 test한다. #rule

> [!abstract] Rule
> Validation docs that number rules need a cross-reference audit whenever a new
> rule is inserted. Renumbering is part of the behavior contract, not markdown
> housekeeping. #rule

> [!tip] happy-path validators
> Validator tests need both reject-path and accept-path fixtures. A populated
> valid graph that round-trips through serde should also pass the validator.

## PR 361

1. 지적 — sentinel detector는 sentinel 전체를 읽어야 한다. 리뷰는
   `scripts/validate-s2m-assets.mjs:82`의 LFS pointer check가 32-byte header만
   읽어서 40-byte prefix인 `version https://git-lfs.github.com/spec/`와 절대
   match될 수 없다고 지적했다. 이런 검증기는 실패 원인이 곧 operator guidance라,
   pointer file을 GLB magic/hash mismatch로 흐리면 remediate path가 틀어진다.
   → `33b13d8f`와 `11c6e044`에서 pointer header read boundary가 48 byte로
   고정되고, GLB negative/partial-prefix/exact-boundary tests가 추가됐다.

2. 지적 — manifest path validator는 literal traversal와 symlink traversal를
   둘 다 막아야 한다. 리뷰는 `scripts/validate-s2m-assets.mjs:224`의
   `path.join` 기반 path resolution이 `../` segment를 해석해 asset root 밖을
   가리킬 수 있고, 뒤이어 symlink redirection도 containment contract를 깨뜨릴
   수 있다고 봤다. Manifest validator는 "trusted committed file"이라도 자기
   contract를 코드로 강제해야 한다. → `33b13d8f`에서 relative containment check가
   들어갔고, `11c6e044`에서 `realpath` containment와 real symlink regression이
   추가됐다.

3. 지적 — validator helper test는 regression의 실제 bridge를 통과해야 한다.
   리뷰는 Windows entrypoint test가 `isEntrypointPath(p, p)`를 호출해 언제나
   true인 tautology라, `fileURLToPath(import.meta.url)` conversion이 되돌아가도
   실패하지 않는다고 지적했다. Cross-platform bug는 "같은 문자열"이 아니라
   URL/native-path boundary에서 재현해야 한다. → `11c6e044`에서
   `pathToFileURL`/`fileURLToPath`를 통해 native path invariant를 test하고, raw
   `file://` URL이 native argv path와 match되지 않는 regression guard가 추가됐다.

4. 지적 — integrity manifest는 silent skip과 silent overwrite를 허용하지 않는다.
   리뷰는 `scripts/validate-s2m-assets.mjs:118` 주변에서 missing `sha256`가 hash
   comparison을 사실상 skip하고, duplicate `entry.path`가 `Map` insertion에서
   조용히 overwrite된다고 봤다. Hash-pinning manifest에서 missing hash와 duplicate
   path는 "나중에 알 수 있는 차이"가 아니라 즉시 실패해야 하는 invalid input이다.
   → `11c6e044`에서 non-empty `sha256` requirement, defensive `validateGlb`
   failure, duplicate path rejection이 추가됐다.

5. 지적 — local-only provenance leak detector는 platform별 absolute form을 모두
   다룬다. 리뷰는 local absolute path 방어가 `/Users`/`/home`/drive path 중심이라
   `/tmp`, `/var`, `/opt`, `/private`, `/Volumes`, UNC, `file://`를 놓친다고 봤다.
   Asset provenance 문서와 manifest는 협업 입력이라 한 번 local path가 들어오면
   재현성을 깨뜨린다. → `11c6e044`에서 POSIX absolute, Windows drive, UNC,
   `file://`를 단일 local-path detector로 reject하고 fixture coverage를 넓혔다.

6. 지적 — LFS-heavy validator와 cheap helper tests는 gate 위치가 달라야 한다.
   리뷰는 `package.json:43` 기준으로 LFS-hydrated GLB가 필요한
   `validate:s2m-assets`를 CI에 무작정 넣는 대신, synthetic helper tests는
   aggregate validation에 들어갈 수 있다고 지적했다. Heavy local validation은
   opt-in으로 두더라도 LFS-free regression tests는 normal docs gate에서 자주
   돌아야 한다. → `11c6e044`에서 `test:s2m-assets-validator`가 `validate:docs`
   chain에 들어가고, README는 hydrated asset validator가 local/workflow-scoped임을
   명시했다.

7. 지적 — asset subset docs는 source fields와 operator failure catalog를 같이
   제공해야 한다. 리뷰는 `assets/s2m_props/README.md:47`의 validation section이
   happy path 중심이고, Source Sets table도 owner/version/license/file mapping이
   부족하다고 봤다. External asset subset은 code보다 provenance와 remediation이
   먼저 stale해지므로, failure message와 fix command가 문서 contract에 포함되어야
   한다. → `11c6e044`에서 source owner/version/license status/files, normalized
   map IDs, non-zero exit behavior, failure-message catalog, `git lfs pull`
   remediation, helper-test command가 추가됐다.

> [!abstract] Rule
> Asset validators should split cheap deterministic helper tests from heavyweight
> hydrated-asset checks. The former belongs in aggregate gates; the latter may
> stay opt-in with explicit operator docs. #rule

> [!abstract] Rule
> Manifest integrity checks fail closed: missing hashes, duplicate paths,
> path traversal, symlink escapes, local absolute paths, and sentinel boundary
> mistakes are invalid inputs, not warnings. #rule

> [!warning]
> Tests for URL/native path bugs must cross the actual representation boundary.
> Passing the same string on both sides only proves equality, not portability.
