# Shotloom devlog 2026-05-22

## PR 396

1. 지적 - diagnostic helper는 이미 가진 owned string을 다시 빌려서 clone하게 만들지 않는다.
   Review는 `SetStageMood` unknown-mood rejection path에서 `mood: String`이 마지막 사용인데도
   `BoundedDisplay::new(mood.as_str())`로 넘겨 `BoundedDisplay::new`의 `impl Into<String>`
   surface가 fresh `String` clone을 만들게 된다고 지적했다. Rejection path는 cold path라
   성능 이슈는 작지만, shared diagnostic helper의 ownership shape는 consistency contract다.
   -> `aaadb67c`에서 unknown mood value를 `BoundedDisplay::new(mood)`로 move하도록 바꿔
   redundant clone을 제거했다.

> [!abstract] Rule
> If a diagnostic wrapper accepts owned input and the caller is at the value's
> last use, move the owned value into the wrapper. Borrowing first hides an
> avoidable allocation and weakens the ownership pattern reviewers can scan for.
