# Shotloom devlog 2026-05-22

## PR 396

1. 지적 - diagnostic helper는 이미 가진 owned string을 다시 빌려서 clone하게 만들지 않는다.
   Review는 `SetStageMood` unknown-mood rejection path에서 `mood: String`이 마지막 사용인데도
   `BoundedDisplay::new(mood.as_str())`로 넘겨 `BoundedDisplay::new`의 `impl Into<String>`
   surface가 fresh `String` clone을 만들게 된다고 지적했다. Rejection path는 cold path라
   성능 이슈는 작지만, shared diagnostic helper의 ownership shape는 consistency contract다.
   -> `aaadb67c`에서 unknown mood value를 `BoundedDisplay::new(mood)`로 move하도록 바꿔
   redundant clone을 제거했다.

> [!abstract] Rule
> If a diagnostic wrapper accepts owned input and the caller is at the value's
> last use, move the owned value into the wrapper. Borrowing first hides an
> avoidable allocation and weakens the ownership pattern reviewers can scan for.

## PR 391

1. 지적 - editor store action surface는 실제 caller가 있는 것만 남긴다. Review는
   Stage mirror store에 `setStages` bulk-write action이 추가됐지만 `apps/editor/src` 안에
   caller가 없고, provider의 shot-scoping guard를 우회하는 ad-hoc write surface로 drift할 수
   있다고 지적했다. Store API는 future convenience가 아니라 current contract라서 죽은 action은
   나중에 더 위험한 entrypoint가 된다. -> `fea0abbf`에서 unused `setStages`를 제거하고,
   `addStage`의 dead `activeStageId` parameter도 제거해 active-id 변경은 provider에서
   명시적으로 처리하게 했다.

2. 지적 - 같은 event family의 shot guard는 모든 branch에서 regression으로 pin한다. Review는
   `stage_updated`만 foreign-shot no-op test가 있고 나머지 Stage lifecycle/edit success
   branches는 동일한 `shot_id` short-circuit을 갖지만 검증되지 않는다고 지적했다. 같은 guard
   모양이라도 public event branch마다 drift할 수 있으므로, shared invariant는 event family
   전체를 table-driven으로 잠가야 한다. -> `fea0abbf`에서 Stage success event branch 전반에
   foreign-shot no-op coverage를 확장했다.

3. 지적 - nullable contract value는 fallback과 clear를 둘 다 test한다. Review는
   `stage_deleted.active_stage_id`가 non-null fallback만 검증되고, bridge contract가 허용하는
   `null` clear case는 빠졌다고 지적했다. `null`과 `undefined`가 서로 다른 의미를 갖는 TS
   mirror에서는 둘 중 하나만 보면 preserve/clear regression을 놓친다. -> `fea0abbf`에서
   `stage_deleted`가 `active_stage_id: null`을 받으면 active Stage가 `null`로 clear되는
   regression을 추가했다.

4. 지적 - nullable collection guard는 sparse fixture로 검증한다. Review는 `stage.elements ??
   []`, `stage.renderables ?? []` guard가 undefined collection을 방어하기 위한 코드인데 test
   fixtures는 항상 populated arrays만 제공한다고 지적했다. Optional collection guard는 populated
   happy path가 아니라 absent-field path가 proof다. -> `fea0abbf`에서 sparse Stage fixture로
   missing `elements` / `renderables` case를 검증하고 Stage가 unchanged로 남는지 확인했다.

5. 지적 - deferred event mirror drift는 default branch TODO나 exhaustiveness guard로 남긴다.
   Review body는 promotion/demotion Stage events가 현재 command gate 때문에 theoretical이지만,
   engine이 emit하기 시작하면 provider default branch에서 조용히 fall through해 store mirror가
   drift한다고 지적했다. Out-of-scope event라도 declared bridge event이면 drift 위험을 future
   reviewer가 볼 수 있어야 한다. -> `fea0abbf`에서 provider default branch에
   promotion/demotion mirror follow-up TODO를 남겼다.

> [!abstract] Rule
> Store reducer APIs are reviewable contract surface. Dead actions, dead
> parameters, and untested optional fields should be removed or pinned before
> bridge event wiring makes them look intentional.

> [!abstract] Rule
> Event-family mirrors need family-shaped tests: every event branch with the
> same guard or nullable contract semantics gets coverage, not only the first
> branch that made the pattern visible.
