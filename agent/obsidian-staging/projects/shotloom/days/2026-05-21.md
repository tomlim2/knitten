## PR 384

1. 지적 - docs merge artifact는 contract reader를 흔든다. Review는
   `docs/ipc/bridge-contract.md`에 authored Stage validator paragraph가 byte-identical
   duplicate로 남아 있어 어느 위치가 canonical인지 알 수 없다고 지적했다. Contract
   docs에서 중복 문단은 harmless duplication이 아니라, 다음 edit 때 둘 중 하나만 고쳐져
   drift를 만드는 seed다. -> `bb3d72e5`에서 duplicate paragraph를 제거하고 주변
   renderable-options paragraph는 그대로 보존했다.

2. 지적 - shared commit helper를 쓰는 handler는 rejection-code surface를 전부 pin한다.
   Review는 missing-shot test가 lifecycle 4개 command만 다루고, 같은
   `commit_stage_edit` shot lookup을 타는 edit 3개 command에는 없다고 봤다. Shared
   helper라도 public command별 rejection code는 각각 contract라, parse/lookup 순서가
   바뀌면 특정 command surface만 조용히 regress할 수 있다. -> `bb3d72e5`에서
   `update_stage`, `update_stage_element`, `replace_stage_renderable` missing-shot cases가
   추가되어 7개 handler 모두 `SHOT_NOT_FOUND` surface를 고정했다.

3. 지적 - event ordering claim은 모든 success event kind로 검증한다. Review는 PR body가
   command-specific event before `bundle_changed`를 claim하지만, test는 `create_stage` 한
   case만 `position` 비교를 하고 나머지 6개는 presence만 확인한다고 지적했다. Ordering
   contract는 event가 "있다"가 아니라 "먼저 온다"라서, event kind별 success path가 최소
   한 번은 순서 assertion을 가져야 한다. -> `bb3d72e5`에서 7개 lifecycle/edit success
   event 모두 command-specific event가 `bundle_changed`보다 앞서는 shared ordering
   regression이 추가됐다.

4. 지적 - bridge handler의 durable mutation은 facade rule 또는 explicit exception을
   통과해야 한다. Review는 `commit_stage_edit`가 `BundleEditor::edit_with_scope`와 같은
   clone/mutate/validate/rollback lifecycle을 bridge layer에 직접 구현해
   `docs/arch/bundle-editor-mutation-facade.md` section 10 item 5를 우회한다고 지적했다.
   Mutation facade rule은 code style이 아니라 future mutation 경로를 한 곳에서 audit하기
   위한 architecture gate다. -> `bb3d72e5`에서 Stage authoring의 temporary exception,
   preserved rollback/dirty-marking invariant, migration commitment가 facade doc에
   명시됐다.

5. 지적 - runtime rejection branch는 bridge contract table에 같은 granularity로 적는다.
   Review는 `replace_stage_renderable`가 wrong-kind asset을 `INVALID_STAGE_PAYLOAD`로
   reject하고 missing asset은 `ASSET_NOT_FOUND`로 reject하지만, rejection table에는
   wrong-kind branch와 embedded `renderable_id` mismatch가 빠졌다고 봤다. Runtime code와
   contract table의 granularity가 다르면 client/debug UI는 어떤 error code를 기대해야
   하는지 잃는다. -> `bb3d72e5`에서 wrong-kind replacement asset과 embedded
   `renderable_id` mismatch rejection rows가 `INVALID_STAGE_PAYLOAD`로 문서화됐다.

6. 지적 - published no-op behavior와 ADR invariant는 같은 예외를 공유해야 한다. Review는
   `set_active_stage` no-op이 bridge contract에는 documented no-op으로 되어 있지만,
   ADR-0026 cross-cutting invariant는 모든 mutating command가 correlated event 또는
   rejection을 낸다고 읽힌다고 지적했다. Runtime이 contract-conforming이어도 ADR이
   예외를 모르면 다음 reviewer는 올바른 no-op을 invariant violation으로 본다. ->
   `bb3d72e5`에서 ADR-0026이 bridge-contract-documented idempotent no-op command를
   correlated event/rejection invariant의 carve-out으로 명시했다.

7. 지적 - PR scope가 issue boundary를 넘으면 title/body가 즉시 truth source가 되어야 한다.
   Review는 PR title/body가 lifecycle issue만 말하는데 diff에는 edit handler commits와
   STL-496 scope가 함께 들어 있어 AGENTS.md "Never do" scope rule과 충돌한다고 봤다.
   Scope split이 실패했을 때 숨기는 것보다, combined scope와 이유를 PR surface에 정확히
   적는 편이 reviewer와 Linear state를 덜 속인다. -> `bb3d72e5`에서 PR title/body가
   STL-495 + STL-496 combined lifecycle/edit scope와 bundling reason을 설명하고, Related
   Issues가 두 issue를 모두 resolve하도록 바뀌었다.

8. 지적 - deferred nits도 tracked follow-up이어야 한다. Review는 raw untrusted id echo와
   per-handler rollback coverage expansion을 nits로 지적했다. 둘 다 merge blocker는
   아니지만, "나중에"가 추적되지 않으면 같은 review debt가 다음 PR에서 다시 발견된다. ->
   `bb3d72e5` response에서 raw id display cleanup은 STL-502, extra rollback coverage는
   STL-503 follow-up으로 분리됐다.

> [!abstract] Rule
> A shared mutation helper reduces implementation duplication, but it does not
> reduce public command contract coverage. Rejection code and event-ordering
> surfaces need per-command tests when each command is bridge-visible. #rule

> [!abstract] Rule
> Architecture gates are either followed or explicitly excepted in the owning
> architecture doc. A temporary bypass without an exception note makes the gate
> unenforceable. #rule

> [!warning]
> When a PR intentionally combines two Linear scopes, update title, body, and
> related issues before review. Otherwise every review finding has to re-establish
> the real boundary from the diff.

## PR 388

1. 지적 - helper signature는 감싼 API의 ownership shape를 흐리면 안 된다. Review는
   `bounded_id(value: impl AsRef<str>)`가 `BoundedDisplay::new`의 `impl Into<String>`
   surface를 다시 borrowed path로 좁히고 owned `String`도 round-trip하게 만든다고
   지적했다. 작은 helper라도 shared diagnostic path면 allocation과 ownership expectation을
   숨기지 않아야 한다. -> `f7c0709c`에서 helper signature를 `impl Into<String>`으로
   맞추고 call site helper는 유지했다.

2. 지적 - bounded display test는 source bound와 escaped render expansion을 분리한다.
   Review는 `BoundedDisplay::MAX_LEN + 32`가 magic bound이고, `escape_debug` expansion이
   control-heavy input에서는 단순 `+1`보다 훨씬 커질 수 있어 false confidence를 만든다고
   봤다. Diagnostic display의 length bound는 input class마다 의미가 달라서 한 mixed
   assertion에 묶으면 실제 보장 범위가 흐려진다. -> `f7c0709c`에서 ASCII-overlong case는
   `MAX_LEN + 18` ceiling으로 고정하고, control-heavy case는 truncation/escaping 성질만
   검증하도록 분리했다.

3. 지적 - shared helper smoke test는 대표 범위를 명시해야 한다. Review는 many rejection
   sites가 같은 `bounded_id` helper를 쓰는데 test는 한 rejection path만 타므로 coverage
   의미가 애매하다고 지적했다. Shared helper라서 representative test가 가능하더라도,
   test name/comment가 그 전제를 말하지 않으면 reviewer는 per-code coverage 누락으로 읽게
   된다. -> `f7c0709c`에서 shared-helper smoke-test scope를 명시하고 ASCII-overlong /
   control-heavy payload classes를 대표 입력으로 고정했다.

4. 지적 - 같은 risk class의 out-of-scope raw echo는 issue로 남겨야 한다. Review body는
   identifier rejection만 bound한 뒤에도 `handle_set_stage_mood`가 caller-supplied
   `mood`를 rejection message와 tracing field에 raw echo한다고 지적했다. 같은 diagnostic
   display risk라도 이번 PR의 identifier-only boundary 밖이면, 묻어두지 말고 별도 Linear
   issue로 이어야 한다. -> `STL-505`가 follow-up으로 남아 mood rejection/log echo hardening을
   추적한다.

> [!abstract] Rule
> Diagnostic display hardening tests should separate source-side length bounds
> from rendered escape expansion. Shared helper tests can stay representative
> only when the shared-helper assumption is explicit. #rule
