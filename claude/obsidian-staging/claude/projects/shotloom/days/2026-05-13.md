# ADR-0047 Tailwind styling default — same-PR self-precedent sweep

## 14:06 — STL-397 closed ([#311](https://github.com/CINEV/shotloom/pull/311))

회고 — ADR-0047 (Tailwind as editor styling default) Proposed 등록. 리뷰 라운드 1에서 `rename-fragile prose` 동일 패턴이 같은 ADR 안에서 두 번 더 적발됨.

**지적 1 — Decision §2가 v3 형태로 token-storage shape을 pin하고, 별도 ADR(0017)이 이미 소유한 Vite 번들러 identity까지 끌어다 씀.** 리뷰어 표현: "the Tailwind v3 shape (`tailwind.config.{js,ts}` with a JS `theme.extend` object)... Tailwind v4's canonical configuration shape is a CSS-first `@theme { --color-*: ... }` block." 원리는 `docs/guidelines/adr-template.md` "Litmus test for durable Decision content" — 도구/통합 reference가 한 단계 위 durable claim 안에 박히면 그 도구의 다음 major 버전 / 교체 즉시 amendment 필요. → `4724f259`에서 단락을 ownership + 공유 토큰 소스 + consumer call site type-check 세 가지 property-level 진술로 재작성. `docs/adr/adr-0047-tailwind-as-editor-styling-default.md` Decision §2.

**지적 2 — Consequences가 `Tailwind's JIT mode emits only used utilities`라고 적었는데 v3 named-mode 라벨.** 리뷰어 표현: "v3 made the JIT engine the default and replaced the classic engine entirely; v4 folded it into the core engine and dropped the named-mode label." 원리는 #1과 동일 — 버전 핀된 용어가 durable Consequences에 들어가면 v4 독자가 "ADR이 stale하거나 v3에 pin됐다"고 읽음. → `4724f259`에서 `Tailwind emits only the utilities actually referenced by the editor's source`로 교체. v3 / v4 / 후속 버전 모두에서 holds.

**지적 3 — 두 finding 모두 `876b73dc`가 이미 PR 안에서 calibrate한 표준의 symmetric application.** PR 둘째 커밋에서 작성자가 `cn()` 도구 pin을 Decision에서 직접 제거했음 — 그 표준을 같은 ADR 안의 두 다른 단락에 일관되게 적용하지 않은 게 round 1의 진짜 defect class. → round 1 fix는 추가 작업이 아니라 **같은 표준의 일관 적용**.

> [!tip] 가장 중요한 배운 것 — PR 내부 자체 precedent를 끝까지 sweep해야 함
> 같은 PR 안에서 한 단락의 v-pin을 직접 제거했다면, 다른 단락에 남은 같은 shape의 v-pin은 **같은 자기-precedent의 미적용**이다. Pre-PR 셀프 리뷰에서 author가 한 번 calibrate한 표준은 같은 문서의 모든 단락에 sweep할 것 — round 1에서 같은 reviewer가 같은 표준으로 두 번 더 지적하는 건 셀프 sweep 갭의 신호.

> [!abstract] Rule
> ADR 안에서 도구·라이브러리·번들러 named-mode 라벨 / `tailwind.config.{js,ts}` 같은 파일-형태 / 특정 major 버전에서만 유효한 용어가 durable Decision / Consequences 본문에 들어가면 defect. property로 진술하라 — "JIT mode emits only used utilities" → "emits only the utilities actually referenced".
>
> #rule

> [!warning] PR 안에서 자기-precedent를 만든 commit (예: `876b73dc`) 는 round 1까지 가기 전 같은 문서의 나머지 단락을 sweep하는 기준이 되어야 한다
> 같은 PR 안의 commit이 표준을 calibrate하면, 그 표준은 그 commit 이후 PR 전체에 retroactive하게 적용된다. `876b73dc`(cn() pin 제거) 직후 같은 ADR의 v-pin 두 단락을 같은 셔틀에서 sweep했어야 함. **교훈:** pre-PR self-review 마지막 단계에 "이 PR 안에서 직접 만든 self-precedent를 같은 문서 전체에 적용했는가" 한 줄 체크 추가.
