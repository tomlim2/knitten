> [!tip] 가장 중요한 배운 것 — 데이터를 바꾸면 그 데이터를 분류하는 prose 도 같은 PR 안에서 같이 바뀐다
> 세 지적 모두 한 결: PR 의 stated purpose 가 "두 preset 의 version prefix 정정" 이었는데, 그 두 preset 을 *분류로 묶는* 한 줄 (`_comment` legend 의 "7..11 backward follow-up") 과 그 분류의 README mirror (bullet list 의 `7..11 — backward follow-up sets`) 와 표 cell (`_backward` Detection criterion) — 세 곳이 모두 옛 분류를 가리키고 있었음. 데이터 변경의 surface 가 JSON 한 줄이라도, 그 데이터를 *enumerate / 분류 / 설명* 하는 prose 는 co-located 라면 같은 PR 의 일부. self-check 단계에서 *"수정한 item 의 식별자 (preset 번호, 파일명, 키워드) 를 같은 디렉토리에서 grep 해서, 그 식별자를 분류하거나 묶거나 예시로 든 prose 가 더 있는지"* 한 번 돌리는 reflex 가 부족했다.

> [!abstract] Rule
> 데이터 파일에서 한 항목의 category/version/label/prefix 를 정정할 때, 같은 파일·자매 파일에서 그 항목을 *index range 로 묶거나 분류로 부르는* prose legend 가 있는지 grep 으로 한 번 확인하고 같은 PR 에서 같이 갱신한다. legend stale drift 는 PR 이 닫고 있는 mismatch 클래스를 한 줄 위에서 재도입하는 형태로 round 2 리뷰에서 잡힌다. #rule #co-located-legend-drift #documentation-standard
