## Shotloom PR #106 리뷰 — APPROVE

hon454 작성 `fix(engine): patch bevy_vrm1 MToon EMISSIVE_TEXTURE via fork` ([STL-116](https://linear.app/cinamon-corp/issue/STL-116)).

### 배경

웹 런타임에서 Spawn Debug Character 시 뷰포트 전체 블랙아웃. MToon shader의 `apply_emissive_light`가 `in.pbr.flags & EMISSIVE_TEXTURE`를 읽는데:

- `PbrInput.flags`는 standard-material flags field
- MToon은 custom material이라 해당 필드 미채움
- MToon의 `EMISSIVE_TEXTURE = 1u << 6u`가 `STANDARD_MATERIAL_FLAGS_TWO_COMPONENT_NORMAL_MAP_BIT`와 비트 충돌
- WebGPU에서는 garbage bit이 set으로 읽혀 HDR tonemap 오염 → 전체 블랙

네이티브(Metal)는 해당 bit이 0으로 읽혀서 안 보였던 문제.

### 수정 접근

`bevy_vrm1` 의존성을 `hon454/bevy_vrm1` 포크 (`patches/v0.7.0`) 로 전환. upstream [#57](https://github.com/not-elm/bevy_vrm1/pull/57)·[#58](https://github.com/not-elm/bevy_vrm1/pull/58)·[#59](https://github.com/not-elm/bevy_vrm1/pull/59)·[#60](https://github.com/not-elm/bevy_vrm1/pull/60)이 랜딩되면 crates.io 복귀 ([STL-137](https://linear.app/cinamon-corp/issue/STL-137) 추적).

### 리뷰 진행

1. 로컬에서 브랜치 체크아웃 시 force-push로 diverged → `git reset --hard origin/claude/angry-hellman-71855b`
2. `pnpm dev:web` → WASM 빌드 ~1분 → Vite 5174 포트 (5173 점유됨). fork된 bevy_vrm1 정상 컴파일 확인.
3. COMMENT 리뷰로 upstream 4개 PR 랜딩 + 로컬 검증 문구 남김
4. 이후 APPROVE 박음 (ryumiel 다른 approve 대기)

> [!tip] force-push된 PR 브랜치는 로컬 diverged를 먼저 해소해야 함
> `gh pr checkout`이 fast-forward 실패로 멈춤. PR 작성자 브랜치는 우리 작업물이 아니므로 `git reset --hard origin/...`로 맞추는 게 정답.

## cci-send-alert 스킬 신규

배경: Slack 채널 `C09DF8A1ZK4`이 새 팀 채널로 배정됨. 용도는 **자동알람** (CI/PR/deploy 상태 signal) — `cci-art-send-notice`의 art channel과 분리.

### 구성

| 파일 | 역할 |
|------|------|
| `skills/cci-send-alert/SKILL.md` | user-invocable, per-message 승인 게이트, disable-model-invocation |
| `skills/cci-send-alert/send.py` | stdlib-only (`urllib.request`) Slack `chat.postMessage` 클라이언트, graceful error |
| `config/slack.json` | `team_channel` + `team_bot_username` 추가 |

### 판단

- **별도 스킬로 분리** — `cci-art-send-notice`에 `--channel` 플래그 추가로도 가능했지만 "무엇을 보내는가"가 완전히 달라서 (art branch life-cycle vs general alert) 책임 섞으면 프롬프트가 지저분해짐.
- **stdlib-only** — `fastmcp` / `slack-sdk` 의존 추가 불필요. `urllib.request`로 `chat.postMessage` 1엔드포인트만 때리면 됨.
- **per-message 승인 유지** — 자동알람이어도 human-in-the-loop. Claude가 직접 못 부르게 `disable-model-invocation: true`.

### 검증

- `python3 send.py --help` → usage 정상
- `python3 send.py "test"` → `{"ok": false, "error": "SLACK_BOT_TOKEN not set..."}` (graceful)
- 커밋: `5822081 feat(cci-send-alert): add team alert Slack sender via Arnyang bot` → `main` push

### 남은 할 일

- `~/.claude/config/.env`에 `SLACK_BOT_TOKEN` 세팅 필요 (다른 머신에서 복사 또는 재발급). 세팅 후 실전송 테스트.

> [!warning] Python 3.9 호환성
> 처음에 `str | None` PEP 604 문법 썼다가 `TypeError: unsupported operand type(s) for |`. macOS 기본 python3 3.9라 `from typing import Optional; Optional[str]` 로 내려씀. 다른 머신에서 3.10+ 보장 안 되면 항상 Optional 패턴 사용.
