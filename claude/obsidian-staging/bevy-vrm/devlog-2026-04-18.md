## PR 요약

- **PR:** [#58 fix: resolve VRMC material handles by index to avoid name-collision skip](https://github.com/not-elm/bevy_vrm1/pull/58)

- **재현:** VRoid export에 `Body_mtoon` 2개 (main body + inner "Bassbody" skin layer). 한 쪽이 unlit-PBR-dark로 렌더되던 문제

## 배운 것

### Merge vs Rebase for fork PR

- `merge upstream/main`: 안전, review thread 유지, merge commit 1개 추가됨
- `rebase upstream/main`: 히스토리 깔끔하지만 force-push 필요 → 리뷰 코멘트 라인 매핑 깨질 수 있음
- **열려있는 PR에 대해서는 merge가 default로 안전**

### glTF material resolution pitfall

glTF spec은 material 이름 unique 요구하지 않음. Bevy `gltf.named_materials: HashMap<String, Handle>`는 이 전제를 깨는 exporter(VRoid)에 취약. Index 기반 (`gltf.materials: Vec<Handle>`)이 robust.

## PR #60 — MToon directional light 버그

- **PR:** [#60 fix: include shadow-less directional lights in MToon direct lighting](https://github.com/not-elm/bevy_vrm1/pull/60)
- **Root cause:** MToon 셰이더 `apply_directional_lights`가 `shadows_enabled` 비트 0인 라이트를 `continue`로 스킵. 하지만 Bevy PBR에서 `shadows_enabled`는 **그림자맵 샘플링 여부만** 결정 — 라이트 자체의 기여는 무관. MToon만 의미를 혼동.
- **증상:** Fill/Rim light (보통 `shadows_enabled: false`) 효과가 MToon 캐릭터에 전혀 안 나타남. 캐릭터만 유독 어둡고 평면적.
- **Fix:** `continue` 제거 → 모든 라이트 accumulate. `shadows_enabled` 체크는 `calc_mtoon_lighting_shading` 내부로 이동, 그림자 샘플링만 gate. 맵 없으면 `shadow = 1.0`.
- **진행:** 메인테이너가 같은 식으로 "CHANGELOG.md 충돌 해결 후 리뷰" 요청 → 해결 + push + 짧은 코멘트.

## PR #59 — MToon emissive texture 버그 (중복 PR 상황)

- **PR:** [#59 fix: surface MToon emissive texture by using material.flags and setting EMISSIVE_TEXTURE bit](https://github.com/not-elm/bevy_vrm1/pull/59)
- **Root cause (2 side):**
  - Side 1: `From<&MToonMaterial> for MtoonFlags`가 `EMISSIVE_TEXTURE` 비트를 설정 안 함 (다른 8개 텍스처는 전부 패턴 맞춰 설정하는데 emissive만 빠짐 — 단순 누락)
  - Side 2: 셰이더 `apply_emissive_light`가 `in.pbr.flags` 읽음. `in.pbr`는 Bevy 표준 PBR input이라 custom material의 flags가 안 들어감. 다른 텍스처 브랜치는 전부 `material.flags` 읽는데 emissive만 outlier
- **증상:** Emissive 텍스처가 영영 샘플링 안 됨 → `emissive_color` factor만 전체 범람 (머리 하이라이트만 발광시키려던 게 전체 표면 발광)
- **두 버그가 서로를 가려주는 관계:** 하나만 고치면 다른 하나 때문에 여전히 증상 재현. Side 1만 fix → Side 2 때문에 `in.pbr.flags`(=0) 읽어 브랜치 안 탐. Side 2만 fix → Side 1 때문에 `material.flags` 비트가 0이라 역시 브랜치 안 탐.
