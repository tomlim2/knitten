# 2026-04-09: main.rs 모듈 분리

### 왜 이 작업을 했나

main.rs가 3,418줄까지 커져서 탐색/수정/리뷰 전부 비효율적. retarget, expression, timeline 등 독립적 기능이 한 파일에 섞여 있어서 변경 영향 파악이 어려움.

---

### 한 일

**모듈 분리 (3,418L → 9개 파일)**

| Module | Lines | Content |
|--------|-------|---------|
| `main.rs` | 129 | mod 선언 + main() |
| `types.rs` | 299 | Resource, Component, Enum, Const |
| `setup.rs` | 409 | setup(), auto_load_fbx() |
| `file_loading.rs` | 505 | 파일 다이얼로그, VRM/FBX 로딩 |
| `retarget.rs` | 301 | apply_retarget_animation, start_playback |
| `expression.rs` | 132 | apply_expression_animation |
| `timeline.rs` | 377 | timeline 시스템 5개 |
| `visualization.rs` | 541 | bone viz, labels, camera |
| `debug.rs` | 744 | retarget debug, log, quality metrics |

**리팩토링 개선 3가지**

1. **VRM 로드 중복 제거**: `load_vrm_resources()` 헬퍼 추출. setup.rs, file_loading.rs(preset), file_loading.rs(dialog) 3곳에서 동일 패턴 반복되던 것을 1개 함수로 통합.

2. **Resource 통합**: `FootSoleOffset` + `FootContactRes` + `GlbVrmRestPose` 3개 → `VrmRestData` 1개. rest_pose 안에 foot_contact가 이미 포함되어 있어서 중복 필드 제거.

3. **system param 축소**: apply_retarget_animation의 파라미터 15개 → 13개. Resource 3개가 1개로 줄면서 자동으로 감소.

---

### 실행 순서

1. types.rs 추출 → `cargo build` (PathBuf import 누락 1건 수정)
2. setup.rs 수동 작성 + 나머지 6개 모듈 병렬 에이전트 위임
3. main.rs를 mod 선언 + main()으로 축소
4. `cargo build` 첫 시도 성공
5. 리팩토링 개선 적용 → `cargo build` 성공
6. `cargo run` 동작 확인 (VRM 로드, retarget, expression, timeline 전부 정상)

---

### 기술 노트

- Bevy system은 함수 시그니처가 ECS에 의해 결정되므로 "인자를 struct로 묶기" 불가. 대신 여러 Resource를 하나로 합치면 param 수 줄일 수 있음.
- types.rs를 먼저 분리하는 게 핵심. 모든 모듈이 types를 참조하므로 순환 의존 방지.
- `pub(crate) fn` 패턴으로 모듈 간 가시성 제어.

> [!tip] 3,400줄 파일도 순수 기계적 분리로 1시간 내에 깔끔하게 나눌 수 있음. 로직 변경 없이 파일만 나누는 건 안전하고 효과적.
