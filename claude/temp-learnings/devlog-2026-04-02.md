# Day 4 (04-02): Identity-rest bone 분석, virtual rest 구현, 아키텍처 정리

### 왜 이 작업을 했나

EXP-002/003에서 VRM 1.0 bone-mesh mismatch의 근본 원인 발견: identity rest에서 three-vrm formula의 dst_rest 보정이 사라짐. 이번 세션에서 해결 시도.

---

## 한 일

### 1. detect_apose() 확장 시도 → 실패

hand/lowerArm pairs를 A-pose detection에 추가. world-space direction 비교가 **bind pose(A-pose vs T-pose) 차이를 잡아서 ~90° 이중 보정** 발생.

> [!warning] world-space direction 비교는 parent chain의 pose 차이를 포함한다
> hand→finger direction을 world space에서 비교하면 arm angle 차이까지 들어옴. parent-local space가 필요하지만 이 접근 자체를 포기.

### 2. IBM에서 bone orientation 추출 시도 → 불가

VRM 1.0 (VRoid) 모델의 inverseBindMatrix에서 rotation 추출 결과 전부 identity (0.0°~0.1°). VRoid는 IBM에도 orientation 정보를 넣지 않음.

### 3. Virtual rest global 구현 (commit `eb09098`)

bone→child direction vector에서 virtual global orientation 계산, identity-rest bone의 dst_rest_global 대체.

```rust
let ref_axis = if side == "left" { Vec3::X } else { Vec3::NEG_X };
let virtual_g = Quat::from_rotation_arc(ref_axis, fwd);
```

**결과:**
- VRM T-pose에서 hand→finger 방향이 이미 ±X에 가까움 → virtual_rest ≈ identity → **hand/lowerArm에 효과 미미**
- Left FK hand fwd_err: virtual ON/OFF 모두 20.7° (변화 없음)
- Right FK hand fwd_err: virtual ON 69.7° / OFF 66.6° (약간 악화)
- **Finger bone에는 유효** (FK 경로, IK가 안 건드림)

> [!tip] VRM 1.0에서 hand bone의 identity rest는 "문제"가 아닐 수 있다
> hand→finger direction이 ±X에 가까우면 identity rest = 올바른 rest. 문제는 identity rest 자체가 아니라 **IK solve 후 hand rotation drift** 또는 **right side formula 문제**.

### 4. 아키텍처 분석 — IK 두 벌 발견

```
FBX → FK (cinev_retarget) → Legacy IK (cinev_retarget/ik.rs) → IK-to-IK (ik_retarget) → AnimationClip
```

| Stage | 위치 | 대상 | 비고 |
|-------|------|------|------|
| FK | cinev_retarget/retargeter.rs | 전체 52 bone | three-vrm + 9가지 보정 |
| Legacy IK | cinev_retarget/ik.rs:787 | arm chain | **redundant** — ik_retarget이 덮어씀 |
| IK-to-IK | ik_retarget/lib.rs | arm chain | proportion map + 2-bone IK + direction |

**Legacy IK 결과가 IK-to-IK에 의해 덮어써짐 — 실행은 되지만 의미 없는 연산.**

### 5. Bone 소유권 정리

| Bone 그룹 | 최종 담당 | virtual_rest 유효? |
|-----------|----------|-------------------|
| spine, head, neck, legs | FK only | N/A (non-identity rest) |
| **fingers** | **FK only** | **Yes** |
| upperArm, lowerArm | ik_retarget IK | No (덮어씀) |
| hand | ik_retarget direction correction | No (덮어씀) |
| hips | FK translation | N/A |

---

## 배운 것

**Identity rest ≠ 항상 문제.** VRM 1.0 hand/lowerArm은 T-pose에서 ±X 방향이라 identity rest가 올바른 rest. virtual rest를 넣어도 ≈ identity가 나옴. bone-mesh mismatch의 진짜 원인은 identity rest가 아니라 IK solve 후의 rotation drift.

**IK가 두 벌 돌면 안 된다.** cinev_retarget/ik.rs (legacy)와 ik_retarget (new)이 둘 다 arm chain을 수정하지만 new가 old를 덮어씀. Legacy IK 제거 필요.

**World-space bone direction 비교는 bind pose 차이를 포함한다.** A-pose detection 패턴을 hand에 적용하면 arm angle 차이까지 잡아서 이중 보정됨.

## 현재 상태

| 항목 | 상태 | 비고 |
|------|------|------|
| Virtual rest (finger) | ✅ | FK 경로, identity-rest bone에 적용 |
| Virtual rest (hand/lowerArm) | ❌ | IK가 덮어씀 + ≈identity라 효과 없음 |
| Legacy IK 제거 | ❌ | 리팩토링 예정 |
| Right side FK hand error 66~70° | ❌ | virtual rest 무관, 원인 미파악 |
| Hand bone-mesh mismatch | ❌ | ik_retarget direction correction이 swing만 처리 |
