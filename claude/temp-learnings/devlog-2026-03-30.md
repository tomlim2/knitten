## bevy-vrm Retarget MetaHuman (R-001~R-012)

### 한 일

**테스트 인프라 구축 (R-001~R-004)**
- VRM 테스트 모델 8개 + FBX 7개 → megamelange에 정리/push
- 네이밍 컨벤션: `{source}_{gender}_{name}`
- cinev_male_body.json config 생성
- T2M Retrieve API에서 male FBX 3개 생성 (walk, wave, f_walk)
- integration tests 15개 + rq_diagnostics 5개 = 20 tests

**headless retarget CLI (R-008)**
- Bevy 없이 VRM rest pose 추출 (gltf crate로 GLB 직접 파싱)
- standalone으로 Retargeter 실행 + RQ diagnostics 출력
- Bevy 뷰어 RQ와 동일한 결과 확인 (scale=1.017, shoulder=0.68, arm=0.94)

**vrm0_compat headless 통합 (R-010)**
- VRM 0.x 자동 감지 + 1.0 변환
- vrm0_compat 모듈을 cinev_retarget에 복사

**fbxcel stack overflow 수정 (R-011)**
- 원인: fbxcel이 아니라 자체 코드의 재귀 topo sort + parent cycle → 무한재귀
- 수정: iterative topo sort + cycle detection + 이중 FBX 파싱 제거
- facial FBX 정상 파싱 (1 bone, 6.7s)

**T2M vs CINEV FBX 분석 (R-012)**
- T2M walk의 팔 동작이 CINEV dance 대비 10-40x 작음 (소스 자체가 약함)
- shoulder slerp(ratio=0.58, blend=0.81)가 19% 추가 감쇠 — 악화 요인

> [!tip] Stack overflow 디버깅은 라이브러리 탓이 아닐 수 있다
> fbxcel 포크/교체를 고려했지만, 실제 원인은 자체 코드의 cycle-vulnerable 재귀였음. backtrace 먼저.

> [!warning] shoulder slerp가 T2M 팔 동작을 죽인다
> female 기준 shoulder_ratio=0.68이면 적절하지만, male은 0.58 → blend=0.81 → 이미 작은 동작을 더 줄임. #retarget #shoulder

## Multi-Agent Ops

### 한 일

- **지통실(1호기) + 2호기 + 3호기** 수동 Orchestrator-Worker 패턴 운영
- `claude/ops/` 디렉토리에 미션별 briefing, timeline, log 관리
- `claude/standards/multi-agent-ops.md` 방법론 문서화
- Agent Teams 공식 기능 조사 — 아직 불안정, 수동 유지

> [!tip] 수동 orchestration이 Agent Teams보다 낫다 (현 시점)
> 토큰 오버헤드 없음, 파일 충돌 직접 제어, 검증을 사람이 함. Agent Teams는 토큰 4x, lead 오작동, resume 안 됨.

### 배운 것

**같은 레포 병렬 작업 시 브랜치 분리 필수**
- 2호기/3호기가 같은 브랜치에서 작업하면 충돌. task-id/agent 네이밍으로 분리.

**dispatch 지시서에 briefing 읽기 포함**
- 에이전트는 이전 컨텍스트 없음. briefing.md 필수.

**커밋은 지통실에서만**
- Worker가 커밋하면 브랜치 꼬임. 지통실이 검토 후 일괄 커밋.
