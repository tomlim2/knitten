# 2026-04-08: Skeleton Remap + Sitting Pose

### 왜 이 작업을 했나

Sitting bind pose 테스트 → hips height 기준 scale ratio가 깨짐 (1.749). 현재 retarget pipeline의 workaround 한계 확인 → VRM skeleton 자체를 FBX에 맞추는 근본 해결 방향 결정.

### 한 일

**Sitting pose 시도**
- male_sitting.fbx 로드 → 캐릭터 옆으로 눕고 비정상 크기
- 원인: hips height 0.587m (앉아서 낮음) → scale_ratio 1.749 (과대)
- SuddenFlutter facial FBX가 body에 영향 주는 건 아님 확인 (body tracks 0)

**Leg-length scale ratio**
- Hips Y 대신 leg chain length (upperLeg→lowerLeg→foot bone lengths) 기준
- Pose 독립적: sitting/standing/lying 전부 동일 ratio (1.153)

**Skeleton remap module 설계 + 구현**
- `crates/cinev_retarget/src/skeleton_remap.rs` 생성
- `compute_remap()`: per-bone offset = fbx_rest_global_yup × vrm_rest_global⁻¹
- `apply_remap_animation()`: FBX delta를 remap space로 변환
- Headless에 remap offset 출력 추가

> [!tip] VRM skeleton을 FBX에 맞추면 three-vrm formula 불필요
> Offset = fbx_rest_yup × vrm_rest⁻¹. VRM 1.0 identity rest → offset ≈ fbx_rest 그 자체.

**Auto diagnostics (headless)**
- Scale ratio sanity check
- Hips height / non-standing pose detection
- Root rotation check
- Static animation detection

### 배운 것

**Hips height는 pose-dependent, leg length는 pose-independent**
Scale ratio에 hips Y 사용하면 sitting/lying에서 깨짐. Bone chain length는 항상 동일.

**Facial FBX는 body 영향 없음**
SuddenFlutter: animated bones=1 (root only), body tracks=0, blend shapes=124. 춤추는 원인은 이 파일이 아니었음 — male_sitting.fbx 자체가 384 frame motion이지만 전 프레임 동일값 (static bind pose).

**Skeleton remap = inverse bind matrix 재계산**
Bone rest rotation 변경 시 skin weight 불변, IBM만 업데이트. mesh 모양 유지. bevy_vrm1 loader.rs에 이미 IBM patch 패턴 있음.

**Phase 9: Skinning 검증 + 수정**
- IBM position: FK propagated position 사용 → 원래 VRM position으로 수정 (diff 1.2m→0m)
- Local translation: `new_t = parent_rot⁻¹ × (orig_pos - parent_pos)` → Bevy FK에서 child 위치 유지
- Bevy FK simulation: 17 bones 전부 diff=0.0000m

> [!tip] Bone rest rotation 변경 시 translation도 같이 보정 필수
> Parent rotation이 바뀌면 child world position이 이동. Local translation을 `parent_new_rot⁻¹ × (child_orig_pos - parent_pos)`로 재계산해야 position 유지.

### 미해결 핵심 이슈

1. **Arm A-pose offset**: VRM T-pose vs FBX A-pose 팔 방향 80° 차이 — skeleton remap 없이는 해결 불가
2. **Walking leg delta 축소**: coord_rot 적용 후 delta가 three-vrm 대비 작음 — 원인 미파악
3. **Bone rest remap의 근본 문제**: coord_rot 적용하면 character tilt, 안 하면 arm 방향 틀림
